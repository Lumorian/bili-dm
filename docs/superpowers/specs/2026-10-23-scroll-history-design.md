# 可上下滚动查看历史弹幕

- 日期:2026-10-23
- 状态:已实现
- 目标:悬浮窗除了「永远只看最新」,还要能**往上翻着读历史** —— 读到一半来了新弹幕,
  不能把画面顶走;想回去就一键回到底部。

## 1. 两条轴分开

| 轴 | 归谁管 | 规则 |
|----|--------|------|
| 数据轴 | `Wall` | 按条数上限(`max_rows`,默认 80)淘汰最旧的;弹幕没有时间 TTL |
| 视口轴 | `Viewport` / `WallWidget` | 屏幕放得下多少、当前往上翻了多少**像素** |

历史深度就是 `max_rows`:它既是内存上限,也是能翻多久。想留更久调大这个数(设置里的
「墙行数上限」),不需要另设一个「历史条数」。

## 2. 为什么是像素级,而不是整行

原实现 `visible_window()` 只挑「放得下的整行」。上滚一点就应该露出半行,整行粒度会让
内容突然跳一行 —— 滚轮和滚动条都没法跟手,滑块也会一跳一跳。

所以 `lifecycle.viewport()` 直接返回 `(row, y)` 列表,y 可以是负数(行被顶部裁一半)。
裁切交给 `painter.setClipRect(PANEL_PAD_Y .. height - PANEL_PAD_Y)`:文字不会渗进卡片
留白(自检:顶部留白带 y∈[0,5) 的文本像素数 = 0)。

`visible_window()` 保留为 `offset=0` 的特例 —— 「自动滚底」这个语义值得有个名字,
滚动路径一律走 `viewport`。

## 3. 贴底 / 离底

`offset` 定义为「距底部往上翻了多少像素」:

- `offset = 0` → 贴底,最新一条必在(`following`;默认态,首次滚动前的所有行为不变);
- `offset = max_offset` → 停在最旧一行;
- 往下滚到底 → 自动回到 `following`(不用按按钮);
- `viewport()` 会 clamp 并把实际值写回 widget:滚到顶之后内容变短(行被淘汰)时,
  内部状态不能停在过期值上,否则下一条新弹幕会按错的基线去加。

**关键回归**:往上翻着看时来新弹幕,`offset` 必须跟着底部一起长(`update_wall` 里的
`added_height()`)。否则「距底部 N 像素」被新的底推走 —— 手没动,画面自己往上漂。

## 4. 交互入口

| 入口 | 行为 |
|------|------|
| 滚轮 | 一次 120 单位 = 3 行(官方聊天列表的手感) |
| 右侧细滚动条 | 4px,落在右侧内边距里不压正文;可点轨道跳转、可拖;悬停变亮 |
| PageUp / PageDown | 一屏(widget 高 − 40px) |
| Home / End | 到最旧 / 回最新 |
| 右下角药丸「↓ N 条新弹幕」 | 点一下回到底部;只在上翻时出现 |
| 托盘「回到最新弹幕」 | 同上,穿透态也能用(不进窗口) |

**放行空白处**:`WallWidget.mousePressEvent` 只接管滚动条与药丸,其余一律 `ignore()`。
解锁后「按住面板任意处拖动窗口」是既有行为,不能被滚动吃掉(有回归测试)。

**锁定态不能滚**:点击穿透时输入区域只放行按钮带,鼠标事件根本到不了墙(这正是穿透的
定义)。所以翻历史要先解锁,和「要打字先解锁」是同一条约定。`hide_when_idle` 在翻着
历史时也让步:不能把用户正在读的窗口隐藏掉。

## 5. 落地位置

| 文件 | 职责 |
|------|------|
| `danmaku/lifecycle.py` | `Viewport` / `viewport()` / `clamp_offset()` / `added_height()` / `scroll_offset_by()`(纯逻辑,无 Qt) |
| `danmaku/wall.py` | 滚动状态、裁切绘制、滚动条与药丸的绘制与命中、滚轮/拖动 |
| `window.py` | 键位(PageUp/PageDown/Home/End)、托盘项、空闲隐藏让步 |
